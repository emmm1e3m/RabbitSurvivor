# 幸存兔开发设计与后续计划

更新：2026-11-04。本文是唯一设计文档，区分当前0.2 demo、后续开发目标和归档原型的历史审计。当前源码与README是已实现行为的依据；下文标为后续或建议的内容尚未完成。

## 1. 最新决定与一致性规则

- 四组选角为课代饼、三好兔、饼狗、兔狗组合；组合包含心好兔与信号狗，共五个形态，不再显示“突击者/游侠/重装”等通用占位角色。
- 五张正式头像分别根据用户原始参考图，通过内置ImageGen全新直接生成“只有头部”的像素图。不是从全身图裁头，不是原图抠图，也不使用手工代码绘制的角色。只允许对完整生成头像做等比缩小，保留耳朵、发型、苹果帽与透明背景。
- 唯一正式资源组为 `public/assets/characters/{classrep,goodrabbit,bingo,heart,signal}.png`。选角、战斗、跟班、界面与图标均使用这一组；不强制适配帽子等挂件，饰品数值和背包仍有效。
- 道具、敌人与环境继续使用脚本离线生成的像素PNG图集；玩家浏览器只加载，不现场生成纹理。
- 竖屏手机采用两列选角和商店、独立滚动面板、安全区留白；战斗顶部显示状态，左下移动，手动模式右下瞄准，技能/道具位于摇杆上方。窄屏保留设置入口，横竖屏切换会暂停。
- 默认开启自动索敌与开火，可在设置中切为手动。手动PC用鼠标瞄准与左键开火，手机使用左右双摇杆：左侧移动、右侧拖拽瞄准并松手射击。
- 普攻冷却与装填共用角色头顶进度条，不在底部另列普攻CD。移动不刷新或延长攻击计时；角色技能与形态切换各按实际可用状态控制。
- 双发与穿透同时适用于远程和近战，具体收益见第5节。
- 苹果双环采用每圈32方向、两圈共64弹；5级强化单枚伤害系数从0.85提升至1.05，不再按等级增加弹数。
- 普通波时间耗尽后，若有待选升级先完成选择，再统一结算场上花朵、饼干币与波次奖励并进入商店；最终波必须击败坏老板。
- **玩家文案不展示开发者元叙述。** 游戏中不堆功能清单、版本完成度、路线图或机制卖点。规则按需进入玩法指南、当前决策界面和“i”详情；每项设置的解释紧跟该设置。实现与开发进度只写在README和本文。

## 3. 当前结构与职责

```text
src/game/types.ts       纯玩法定义和运行状态
src/game/content.ts     静态内容注册表与边界校验
src/game/Session.ts     一局状态、攻击、敌人、成长、交易与流程
src/main.ts             App装配、DOM界面、设置、键鼠与双摇杆输入
src/WorldScene.ts       Phaser世界显示、相机、角色/怪物与效果
src/DetailsView.ts      根据内容和实时状态生成i详情
src/ShopView.ts         商品收益、价格与购买状态
src/style.css           响应式像素界面
src/audio.ts            程序化音效
art/sprites.mjs         道具、敌人、环境像素源
art/characters/prompts.json  正式头像实际提示词与生成来源
scripts/                离线素材准备、玩法与资源检查
public/assets/          静态PNG、图集JSON与manifest
public/fonts/           本地中文像素字体及许可
archive/                独立旧版归档
```

App创建并拥有Session，WorldScene通过host读取同一会话，DOM覆盖界面调用会话动作；不再另造全局SessionManager。结束后只记录一次结果，重开创建新会话。Session不依赖Phaser或DOM；表现层读取结果，不重复结算伤害、货币或购买。

目前Session仍集中部分战斗、生成和流程逻辑。新增机制导致职责确实拥挤时，依次提取攻击/伤害、敌人行为和库存交易；不为了形式先拆成十几层服务。保留当前直接依赖与可读函数，避免旧入口和新入口同时结算。

## 4. 注册表与扩展约定

注册表采用静态TypeScript记录和直接导入。定义保存规则，Session保存可变状态；不引入运行时插件、反射扫描、表达式语言或通用ECS。

| 注册表 | 当前定义内容 | 消费方与扩展路径 |
| --- | --- | --- |
| characters | 名称、描述、形态、初始形态、基础属性、能力、近战属性 | 选角/详情/会话引用，角色不复制整套UI |
| enemies | 名称、贴图、HP/伤害/速度/半径、经验/币、行为类别 | 生成、战斗；已有AI变种直接增定义，敌人i/图鉴为后续 |
| items | equipment/consumable类别、价格、层数、属性/效果、主动action、每局取得限制、可选装扮引用 | 商店、背包、获得/使用与详情共同读取 |
| abilities | 名称、图标、描述、冷却与行为类别 | 角色能力执行、按钮和详情 |
| upgrades | 名称、图标、属性、数值、可选加成上限 | 三选一候选与统一属性结算 |
| cosmetics | 名称、素材、视觉槽 | 当前仅保留元数据；不等于已完成穿戴系统 |
| stages | 波次、时长、刷怪间隔、HP缩放、奖励、敌人权重、Boss目标 | 普通波与最终战流程 |

`types.ts`与`content.ts`是当前字段契约的唯一来源，文档不再复制一套逐渐失配的完整接口。内容ID稳定，不随展示名或文件名改变；当前按登记键与定义id一致进行检查。

### 新内容分两种

1. **现有机制的新内容**：增加定义、素材并登记一次。普通属性饰品使用statBonuses，现有效果使用effectBonuses；同类敌人复用behavior和参数。商店、背包与i详情读取同一目录，不添加具体内容ID分支。
2. **新的规则**：增加相应行为实现与必要类型。出现第二个复用相同行为的内容时，再提取小型工厂表；不假定任何玩法都能只靠JSON实现。

角色切换、成长和跟班目前存在少量角色专属判断；未来这些规则增加时，优先提取角色被动处理器，而非继续扩展主循环里的角色ID判断。props、掉落表和独立武器注册表按新增内容需求逐步提取，当前树/桶不为形式统一立即重写。

### 具体接入操作

| 新增项 | 必要改动 | 不应修改 |
| --- | --- | --- |
| 普通属性饰品 | 登记ItemDef的价格、上限、statBonuses与图标 | 商店/背包/详情的内容分支 |
| 同AI怪物变种 | 登记EnemyDef并配置波次权重 | UI和主战斗流程 |
| 新升级选项 | 登记UpgradeDef属性、数值、候选上限 | 三选一布局和属性结算 |
| 已有能力的新角色 | 登记角色、形态与静态头像 | 选角布局和操作系统 |
| 全新AI/技能 | 增加对应处理器及定义引用 | 其他角色的代码与UI |
| 新装扮 | 待穿戴功能实施时增加CosmeticDef及素材 | 不通过显示与否改变属性 |

注册并不意味着自动解锁、无条件进入所有商店或出现在所有波次；出现条件、上限和波次权重仍要明确登记。

### 状态与事务

- 内容定义只读。生命、冷却、弹匣、库存、余额、经验和波次属于本局运行状态，不能写回定义。
- 被动持有量是叠加层数来源；效果汇总由持有量计算。一次性道具由槽位保存，成功使用消耗，失败不消耗。
- acquired记录本局累计取得量，与当前库存用途不同。灯用完、切换、复起或增加槽位不清零取得记录。
- 购买验证商品批次、售出状态、余额和库存限制后统一提交；不能由UI先扣币、Session再扣一次。
- 角色技能冷却与兔狗共享状态不在HUD另存；移动、弹窗重绘或形态切换不重置。
- 攻击、持续状态和实际治疗使用战斗时间，暂停/升级/商店不偷走冷却或无敌时长。
- 结果、击杀与奖励只在首次对应转换时结算；重开不残留旧局攻击、监听或计时。

满槽替换是后续功能。实施时，商店/地图共用先选择再提交的接收入口；取消不扣币、不记取得、不标售出。当前简单槽位足够，只有需要移动/替换并保留实例状态时再引入稳定实例ID。

## 5. 操作、战斗与收益规则

### 输入与显示

默认autoAim开启。关闭后，PC鼠标方向与左键按住状态传入玩法，手机右摇杆传入瞄准向量并在松手时请求射击。左摇杆独立绑定触点，技能、切换与道具不抢移动触点。失焦、触点取消与横竖屏改变时清空输入并暂停，避免粘连移动。

菜单、升级和商店支持点击/触摸及WASD/方向键选择、空格/回车确认；战斗空格仍是技能。视口使用浏览器可用尺寸和RESIZE，世界坐标、相机与界面布局分离，不把固定1280×720桌面画布缩到手机上。

普攻/装填进度只显示于角色头顶。技能与道具按钮发动作，玩法判断是否可用。当前详情i解释角色、技能、饰品、升级和武器；尚无敌人i入口，不在首页堆开发功能清单。

### 近战与远程共享装备收益

- 远程双发增加弹丸，普通攻击总弹丸最多3；穿透最多额外穿过2个目标。
- 近战双发追加挥击，最多3段，后续段造成首段65%的伤害，不把完整伤害无条件复制三次。
- 近战穿透每层增加每段可命中的一个最近有效目标，并增加8范围；最多每段3个目标。攻击仍尊重瞄准方向。
- 装备描述与i详情同时说明近战/远程收益，避免买到对当前攻击类型无用但文案未说明的道具。
- 爆炸不重复触发同一种击杀爆炸；回血只认实际回复，满血拾取和盾刷新不伪造治疗量。

### 波次与资源

地上花是真实可拾取资源，不放置不可采的同形花作装饰。花与饼干币均经统一收益入口；三好兔拾取加成随来源正确作用。

普通波时间耗尽后，有待选升级时先停留升级界面。最后一次选择在chooseUpgrade中恢复running，随后下一次step进入finishWave：先结算未拾取的花/币，清理战场，再发波次奖励、处理波后成长并进入商店。不能重复入账。回血苹果和未取得的一次性道具不会被当成自动获得的币。最终Boss未击败时不执行普通波清场判胜。

### 当前角色特色

| 角色 | 当前规则 |
| --- | --- |
| 课代饼 | 每个普通波后+3%伤害与1最大生命，第3/6次波后成长获得跟班，最多2名；苹果双环每圈32方向、两圈共64弹，5级仅增强单枚威力 |
| 三好兔 | 拾取币收益+50%，每持有5币伤害+1%，最多+30%；消费后随余额回落 |
| 饼狗 | 苹果近战、22%最大生命的苹果盾，波初补盾、实际治疗缓慢补盾 |
| 心好兔/信号狗 | 共享生命与技能冷却，切换间隔4秒；心好兔远程，信号狗近战 |

备用生命尚未实现。若后续加入，先采用每局一次、恢复部分生命和短暂保护的有限收益，避免同时赠送双形态与两条满血。

### 一次性道具与长期成长

地图与商店共享取得规则；道具栏从1格开始，前两次真正通关各加1格，最多3格。容量不等于自动赠送物品。当前满槽无法取得新道具；替换功能待做。

灯每局最多取得1次，使用消耗但11.2秒无敌持续状态继续存在，不能因移除道具而撤销；不会因切形态再次补发。取得限制跨地图与商店生效。

击败Boss解锁可选挑战0–3，普通档保持固定基线，不按累计通关次数无上限提高怪物。长期奖励后续优先扩充外观、图鉴与明确机制，避免无限槽位或无限血量倍率。

## 6. 头像与离线素材管线

### 五张正式角色头像

原始身份依据是五人参考图中的课代饼、三好兔、心好兔、信号狗，以及独立饼狗图。参考第五位饼哩未额外加入可玩角色。

| 形态 | 保留的头部特征 |
| --- | --- |
| classrep / 课代饼 | 深色短发、红色眼镜、人耳与脸颊细节 |
| goodrabbit / 三好兔 | 奶黄长耳、额头两笔、慵懒眼神 |
| bingo / 饼狗 | 白色垂耳、红苹果帽、顶部绿叶小装饰 |
| heart / 心好兔 | 白粉长耳、粉色额毛，头像额毛处的小红心 |
| signal / 信号狗 | 白粉垂耳、粉色额毛与耳部Wi-Fi标记 |

五张头像是五个独立内置ImageGen请求，提示词明确HEAD-ONLY，源输出均为正方形头部，无身体；不是旧全身结果裁切。实际提示词和生成文件ID保存在 `art/characters/prompts.json`。

`scripts/prepare-character-images.mjs`仅整体等比缩为512×512并保留透明通道，不裁图、不去身体、不绘制像素。正式PNG直接入库，CI不调用生成服务。原始参考目录、生成中间结果和预览不发布。

`scripts/extract-characters.mjs`是整理身份参考的辅助工具，默认输出 `.verify/reference-cutouts`，不会生成正式头像，不在当前构建流程中。

### 其余素材

`art/sprites.mjs → scripts/build-assets.mjs → public/assets/atlas.png + atlas.json + manifest.json`，在开发/CI离线执行。游戏加载图集并摆放/播放资源；不现场生成静态纹理。正文中文像素字体使用本地文件，保留许可。

资源路径统一解析部署base，兼容 `/RabbitSurvivor/`。预警、弹丸、角色和拾取物要有足够对比度，纯外观变化不改变碰撞体与数值。当前未强贴装扮；后续穿戴若恢复，须以独立CosmeticDef控制视觉槽，与道具属性分开。

## 7. 数值基线、审查与验证

### 当前demo基线

当前数值以 `src/game/content.ts`、`Session.ts` 为准。以下已落地，不能与原型审计值混用：

| 项目 | 当前实现 |
| --- | --- |
| 经验 | 下一等级需要 `50 + 10 × (等级−1)` XP |
| 武器 | Lv1–5；每级增加20%基础伤害，同级加算 |
| 伤害 | 基础攻击×武器倍率×（1＋升级/饰品/训练/持币等同层加成） |
| 攻速/暴击 | 攻速最多2.2，暴击率最多45% |
| 防御/恢复 | 护甲最多24，恢复最多2HP/s，饼狗盾最多22%最大生命 |
| 普攻组合 | 弹丸/近战段数最多3，穿透额外次数最多2 |
| 爆炸 | 两层最多30%击杀触发率，不自连锁 |
| 商店 | 刷新价 `4 + 已刷新次数×3`，饰品各有上限 |
| Boss/挑战 | 基础3000HP；挑战HP与伤害采用有限阶梯，最高挑战3 |

有上限不代表难度已平衡。伤害、攻速、暴击、目标数、护甲、恢复和角色收益仍会相乘或形成正反馈；需结合命中率、走位与手机输入测有效输出，不能只看静态面板。

### 原型历史审计

归档原型曾使用固定50XP一级；按默认难度连续刷怪、全击杀/收集、树桶全清的理想估算，10波约3086XP，可能产生61次升级选择。旧普通攻击连续时间估算约19.7 DPS，旧武器每级+30%；这些不是当前demo的测量结果。

原型还存在悬赏只加长队列而不改变出场容量、最终Boss超时直接胜利、无上限多重/穿透/爆炸链及恢复叠加等风险。新版已采用递增经验、有限叠加与Boss目标；问号悬赏未移植，未来恢复时必须让风险真实出场，不保留近似免费金币。

### 最小必要的调参检查

- 常规、新档与满成长分别评估，不把解锁3槽误认为自动拥有3个强力道具。
- 专测多重＋穿透＋爆炸、护甲＋恢复＋盾、经济＋持币增伤；近战和远程都参与。
- 测灯对Boss决战的影响，避免无敌时间内稳定无风险秒杀，也避免不携灯无法合理通关。
- 记录每波实际生成/击杀、有效伤害、实际治疗、币收入/支出、升级次数、道具取得/消耗和Boss击杀时间。
- 随机种子和小型断言用于复现规则；真人及手机路线用于判断难度、信息可读性和操作负担，不预设通关率保证。

## 9. 发布与维护验收

1. 冷缓存/慢网始终有加载反馈，音乐慢或失败不阻止开局；正式角色只从统一五张静态头像读取。
2. 桌面、手机横屏和竖屏完成菜单→选角→战斗→升级→商店→Boss→结算→重开，手机全程不用键盘。
3. 默认自动与设置切手动都有效；PC左键和手机双摇杆的方向、释放与取消正确，失焦/旋转后不粘连输入。
4. 普攻与装填进度仅头顶显示；移动不重置CD，近战双发/穿透产生与描述一致的收益。
5. 花朵可采集，波末花/币仅结算一次，升级连续选择后正确进商店，最终Boss未击杀不会判胜。
6. 新增已有机制的饰品或敌人只需增加定义与素材/波次登记；UI和主循环不增加具体内容ID分支。
7. 灯取得/使用、共享冷却、叠加上限、购买和结算仅处理一次；重开不残留旧局状态。
8. `npm run check`、类型检查与生产构建通过，再验证Pages脚本、图片与音频资源及主页入口。归档和开发中间产物不发布。
