# 幸存兔

[在线游玩](https://emmm1e3m.github.io/RabbitSurvivor/) · [个人主页](https://emmm1e3m.github.io/)

电脑、手机都能玩的果园生存游戏。当前为0.2 demo：课代饼、三好兔、饼狗，以及心好兔与信号狗组合；一局8波，穿过草地、树林、沙滩与海里，击败最后的坏老板获胜。局内通过波后商店购买饰品和武器强化，局外通过成长树学习永久本领。

## 运行与验证

需要Node.js 22.12+，CI使用Node.js 24。

```sh
npm ci
npm run dev
npm run check
npm run build
npm run preview
```

画布使用浏览器当前可用宽高，随窗口与横竖屏调整，不设置固定分辨率。音乐在开始后后台加载，失败也可静音游玩。

## 操作与流程

默认开启自动索敌与开火，可在设置中关闭并切为手动。移动不改变攻击冷却。

- 界面：WASD/方向键选择，空格/回车确认，也可直接点击或触摸。
- 电脑战斗：WASD/方向键移动；手动模式用鼠标瞄准、按住左键连射；空格放技能，Q切换兔狗，1/2/3使用道具，Esc暂停。
- 手机战斗：左摇杆移动；手动模式按住右摇杆连续射击，拖动调整瞄准，松开或取消即停止；技能、切换和道具使用独立按钮。
- 普攻冷却与换弹只显示在角色头顶；技能和兔狗切换用进度条显示冷却，不显示倒计时数字。生命、护盾分开显示，树、桶、跟班和Boss有各自世界血条。
- 角色、技能、饰品和成长节点旁的“i”打开对应详情；首页和结果页的“成长”进入局外成长树。

局内没有经验、角色等级或升级三选一。前7波存活到结束后，未拾取的花和饼干币自动结算，发放波奖并进入商店；第8波必须击败坏老板才获胜，超时不会直接通关。第1–2波草地、3–4波树林、5–6波沙滩、7–8波海里；没有手动难度选择。

自然结束的成长积分为抵达波次×5，通关额外+10：首波战败5、第7波战败35、第8波战败40、通关50；主动结束0，均只结算一次。成长树分攻击、生存、灵巧三枝，各3节点，购买立即保存、下次出发生效。

通关使下局威胁提高1级，最高4级；战败或主动结束不提高威胁。每波开始再依据当前构筑做小幅成长补偿，波内不追涨。同一威胁下卡关仍能累积积分购买成长，有限补偿只吸收部分增益，保留变强的优势。

## 当前实现

- 四组选角、五个形态。五张正式头像分别根据用户原始参考图，由内置ImageGen全新生成头部，统一使用透明PNG；选角、战斗、跟班、界面与图标共享这组资源。
- 课代饼每3个普通波招募1名独立生命、位置和攻击计时的苹果跟班，最多8名存活；死亡不自动复活。苹果双环每次基础施放两圈共64弹，第5波起强化单枚威力。三好兔拾币收益与持币增伤；饼狗近战和苹果盾。
- 兔狗共享生命与主技能冷却，切换短暂加速/保护；心好兔技能冲锋，信号狗召唤命中后消耗的环绕苹果。
- 普攻和角色技能共享伤害、双发、穿透、暴击及击杀效果快照；技能按各自机制处理追加施放或命中额度。近战可挥掉普通敌弹，预警后的激光和区域攻击不可格挡。
- 饼干怪、音符怪、冲刺、自爆、激光与区域攻击敌人，苹果树、炸药桶与坏老板。Boss基础2200HP，通关威胁与小幅成长补偿叠乘，具体上限见设计文档。
- 有限叠加饰品、背包、商店购买/刷新、真实花朵拾取、波后收益，以及三枝9节点的局外成长树。
- 地图与商店一次性道具；灯使用后消耗，无敌持续11.2秒，本局最多取得一次。前两次累计击败Boss各解锁一格道具栏，最多三格。
- 离线像素地面与点缀覆盖四种场景；海里有游鱼与泡泡，沙滩/海里树分别使用矮棕榈/珊瑚苹果树外观。共享字号、按钮、面板与“i”详情组件，保留加载反馈、暂停/失焦保护、声音与震屏设置。

角色不强行适配帽子等挂件。饰品仍提供数值与背包显示；装扮定义不等于已实现完整穿戴系统。

独立图鉴/成就页面、问号事件、高级备用生命、满槽替换和独立装扮选择仍待完成；当前满槽不接收新的一次性道具。局外成长树已经重建，不能与尚未实现的图鉴混称为待移植。数值仍需真人和手机实战调优。

## 开发结构

```text
src/game/content.ts          角色、道具、敌人、能力、成长节点、装扮和波次静态注册表
src/game/Session.ts          一局玩法状态、战斗、波后交易与胜败结算
src/game/MetaProgress.ts     Profile v2、成长节点状态/购买、存档规范化
src/game/types.ts            纯玩法契约
src/main.ts                  页面界面、存档、动作与浏览器输入
src/WorldScene.ts            Phaser世界表现、血条、预警与相机
src/WorldBackdrop.ts         四种biome的离线地面、点缀与海底动效
src/DetailsView.ts           按内容生成详情
src/ShopView.ts              商店商品与购买状态
src/MetaView.ts              局外成长树、前置/等级/积分与购买入口
src/style.css                全局视觉token与响应式组件
src/audio.ts                 程序化音效
art/sprites.mjs              道具、敌人与环境像素源
art/characters/prompts.json  五个正式头像的实际ImageGen提示词与输出来源
scripts/                     素材准备、离线生成与玩法/资源检查
public/assets/characters/    唯一一组正式ImageGen像素头像，五张透明PNG
public/assets/               离线生成的道具、敌人和环境PNG图集
archive/prototype-2026-11-04/ 原始游戏完整源码归档，不参与构建或发布
```

普通属性饰品登记statBonuses、图标和价格；成长节点登记分枝、前置、费用、maxRank和加成。商店、成长页与详情读取同一目录；全新能力或AI才增加对应行为实现，不预建插件系统。

`npm run check`覆盖内容/素材引用、8波胜败与波后商店、成长积分和购买前置、波初动态难度、灯、共享冷却、技能/装备联动、近战格挡、跟班伤亡及收益结算。自动检查覆盖规则与状态，不能代替真人难度评估。

## 素材与音乐

- 角色由内置ImageGen逐个根据原始参考直接生成“只有头部”的像素图，实际提示词和生成文件ID保存在`art/characters/prompts.json`。
- `scripts/prepare-character-images.mjs --sources <路径映射JSON>`仅对完整头像等比缩小并保留透明通道，不裁切全身、不代码重绘。正式文件为`public/assets/characters/{classrep,goodrabbit,bingo,heart,signal}.png`。
- `npm run assets:build`在开发/CI阶段生成道具、敌人与环境图集；浏览器只加载PNG。CI直接使用已入库头像，不调用ImageGen。
- `scripts/extract-characters.mjs`仅整理原始身份参考，默认输出到`.verify/reference-cutouts`，不生成正式头像或进入构建。原始参考与开发预览不发布。

BGM为已入库的`public/audio/orchard-futurebass.mp3`：保持音高加速至1.25倍，估计120→150 BPM、121.6秒；原旋律主体采用11.025kHz采样保持与8bit量化，湿/干92%/8%，另配future bass和弦、低音、侧链及鼓组。浏览器只播放成品。

重制时在安装FFmpeg/ffprobe的开发机执行`node scripts/build-music.mjs`；普通构建和CI不需要FFmpeg。参数与测量在`art/audio/remix.json`，制作说明见`art/audio/README.md`，原曲保留在归档中。

完整开发依据与后续清单见[重构设计方案](docs/重构设计方案.md)。推送main后GitHub Actions构建并部署Pages。
